# `inference/mcs.h` testing: what each suite checks

`docs/MCS_DOCUMENTATION.md` is the header's reference, read while writing a call; `docs/MCS_PERFORMANCE_DOCUMENTATION.md` is read while changing the implementation; `docs/MCS_RELIABILITY_DOCUMENTATION.md` while deciding whether to believe a set. This file is read before changing the header, or when a suite fails, to find what each check is holding in place and why it is written the way it is.

It was the largest section of the reference file and took that file past the size `README.md`'s documentation-structure policy allows, and it splits off on the policy's own criterion: a caller writing a call does not need to know how the report writer's column alignment is asserted, and someone changing the header does.

## The suites

| file | the question it answers | how it runs | time |
|---|---|---|---|
| `tests/correctness/test_mcs.c` | does every entry point compute what its definition says | `make test` | 0.03 s |
| `tests/correctness/mcs_primitives.c` | do the structural primitives compute what they claim, and does a loop built from them reproduce `mcs` | `make test` | 0.02 s |
| `tests/correctness/test_mcs_variance.c` | how the three variance estimates differ in size, on the shipped code path | `make test` | 3.2 s |
| `tests/correctness/mcs_size_and_power.c` | does the set still cover what Theorem 1 promises, and still eliminate what it should | `make test` | 0.27 s |
| `tests/correctness/mcs_settings_study.c` | which settings a set needs to be worth reading | `make study-mcs_settings` | 50 s |
| `tests/integration/frame_to_model.c` | does a loaded column reach this header's arithmetic intact | `make test` | |
| `tests/performance/mcs_candidates.c` | does a candidate rewrite agree with the shipped header, and is it cheaper | `make bench-mcs_candidates` | |

Times are best of three wall-clock runs on the machine every number in these documents was measured on, 16 cores. `test_mcs.c` and `mcs_primitives.c` take `STRESS=1` for a heavier pass. `make test-mcs-candidate MCS_CANDIDATE=<header>` runs the four `make test` suites under `tests/correctness/` against a candidate instead of the shipped header; `docs/MCS_PERFORMANCE_DOCUMENTATION.md` describes that gate and the harness beside it, and `docs/MCS_RELIABILITY_DOCUMENTATION.md` holds everything `mcs_size_and_power.c` and `mcs_settings_study.c` have measured.

## `tests/correctness/test_mcs.c`

`tests/correctness/test_mcs.c` compares against independent double reference implementations written from the definitions, not by calling `inference/mcs.h`: in particular the pairwise references form both `(i,j)` and `(j,i)` explicitly, so the header's `d_ji = -d_ij` storage shortcut is checked rather than assumed, and the "mean of the others" reference sums the other `M-1` models directly rather than subtracting from a total.

Known values: a hand-computed two-model case (`[1,2,3,4]` against `[1,1,1,1]`, giving `gamma_0 = 1.25` and `t = 1.5/sqrt(0.3125)`) checked through `mcs_tstats` under both statistics, `mcs_statistic`, `mcs_worst`, and `dm_test`, so five entry points must agree on one hand-derived number; hand-computed `mcs_loss` output for all three loss kinds, with the loss columns' names checked to be the forecast columns' names and a loss column's mean checked against `stats_mse`; and a string column added to both the source and the loss table, which must change neither the model count, the model names, nor the statistic.

The two windows get their own hand-computed contrast on the same `d = [0,1,2,3]` at truncation lag 1, where they differ: rectangular gives `2*pi*f = 1.25 + 2(0.3125) = 1.875`, Bartlett gives `1.25 + 2(0.5)(0.3125) = 1.5625`, i.e. a standard error of exactly `0.625` and `S_1 = 2.4`. The `DM_NEGATIVE_VARIANCE` path is triggered deliberately with a `+1/-1` alternating loss differential, where `gamma_0 = 1` and `gamma_1 = -(n-1)/n` make the rectangular estimate negative while Bartlett stays positive on the same data.

Structure: `mcs_block_indices` is checked for range, for consecutive indices within a block (the property that makes it a *block* bootstrap, and one that a broken start-plus-offset would still satisfy in range), for both degenerate block lengths, for a truncated final block, and for reproducibility.

Randomized: 120 fixed-seed runs (`n` up to ~70, `M` up to 6, lag up to 11, AR(1) losses so the HAC lag has work to do) comparing every stored t-statistic, `mcs_statistic` and `mcs_worst` against the reference under both statistics, asked for under `MCS_VARIANCE_HAC` since that is the form the references compute; 200 fixed-seed `dm_test` runs against the reference including its p-value and its `status`, alternating between the two windows run to run so the negative-variance branch is reached by the reference and the implementation together.

Behavior: `dm_test` rejects at most 8 of 40 fixed-seed runs under a true null (a nominal-5% size check) and 10 of 10 under a mean loss gap of two noise standard deviations per observation, with the correct sign. `mcs` on four models at mean losses `1.0, 1.0, 1.6, 2.4` must drop the two worst in order and keep exactly the two tied best, under both statistics.

Invariants over 30 randomized runs: the surviving set and the elimination order partition the model indices exactly and their sizes sum to `m0`, every reported name matches `mcs_model_name` at its reported index, the surviving set is ascending, p-values are in `[0,1]`, an eliminated model's p-value never decreases along the elimination order, every survivor's p-value beats every eliminated model's, and an unconverged result has exactly one survivor.

The p-value contract gets its own test, on five models with two tied at the bottom, under each of the three variances: `mcs_in_set(&r, j)` and `r.pvalue[j] >= opt.alpha` agree for every model, which is Theorem 4 on the returned numbers; exactly one model sits at `1.0`, the convention `P(H_0,M_m0) = 1` belonging to the last model standing and to no other; and at least one *surviving* model carries a p-value below `1`, which is the number a run that stopped at the accepted test could not report.

The three variances get a paired test: the first round draws its blocks the same number of times in the same order whichever variance is in force, and under the null used the first round decides, so on one dataset and one seed the p-values compared come from identical resamples. From the second round on they would not, since the bootstrap variance reuses the first round's draws and the HAC variants draw afresh. Under a true null with serially correlated losses, `MCS_VARIANCE_HAC_RESAMPLE` must give a strictly larger round p-value than `MCS_VARIANCE_HAC` — the direction the measurement in `docs/MCS_DOCUMENTATION.md`'s **The three variances** explains — while `MCS_VARIANCE_BOOTSTRAP` and `MCS_VARIANCE_HAC` land within `0.1` of each other. The two HAC variants must also return bit-identical observed t-statistics from `mcs_tstats`, since they differ only in the bootstrap. Separately, `mcs_worst(&L, o)` must name the model `mcs(&L, o)` dropped first under all three, which is what pins the primitives to the run.

A separate test frees the input `DataFrame` and then reads the result's names, which is what the deep copy is for. Raising `alpha` on identical data and an identical seed must eliminate weakly more models *in the same order* — the smaller `alpha`'s elimination order is a prefix of the larger one's, which fails if the loop is taking a different path rather than simply stopping earlier.

Reporting: `mcs_in_set` is checked against a direct scan of `surviving[]` for every model, with the counts and the eliminated models cross-checked. `mcs_effective_hac_lag` is checked on all four of its cases (derived, explicit, clamped, explicit zero), and then against `mcs()` itself under `MCS_VARIANCE_HAC`: spelling the derived lag out explicitly in the options must reproduce a run bit for bit, which fails if the two derivations ever drift apart. `mcs_fwrite_options` is checked to report *that* lag rather than a recomputed `block_length - 1`, to name whichever statistic was set, and — under the default variance, which reads no lag — to report no truncation lag at all rather than one the run never used. `mcs_pvalue_frame` is checked row by row against the result it came from and against `stats_mean` of the loss column, for column types and order, for its `in_set` column summing to `n_surviving`, and for being an independent copy — freeing the loss table must leave the frame intact. The report writers are rendered into memory with `open_memstream` rather than onto the filesystem, so the text itself can be asserted on: the title first (and absent when `NULL`), every model name present, each model's own p-value on its own row in the format the writer promises, the `in set` marker exactly where `mcs_in_set` says, the elimination list in elimination order rather than column order, `none` when and only when nothing was eliminated, the right sentence for each of the two termination cases, and — the alignment claim — the mean-loss column's decimal point landing at one offset across every row, including a run whose model name is 45 characters long. `dm_fwrite_report` gets one case per `DMStatus`. The p-value's range is checked on a hand-built pair rather than a draw: `loss_a` is `0` throughout and `loss_b` alternates `1 ± eps`, so the differential's mean is `-1`, its `gamma_0` is `eps^2`, and at truncation lag `0` over 100 observations `S_1` is exactly `-10/eps`. Both `eps` values used are negative powers of two, so `1 ± eps` is exact in the loss table's `mreal` storage under either build and the statistic really is exact. `eps = 0.5` gives `S_1 = -20` and a p-value near `5.5e-89`, checked to relative accuracy against `special_norm_cdf` — a number the old `mreal`-typed field could not hold at all. `eps = 0.25` gives `S_1 = -40`, whose tail near `1e-349` is past what a double holds even in subnormals, so the p-value is genuinely `0` there and the report says so.

Rounds: the rounds are checked on every run that goes through the structure test — the randomized, adversarial and stress runs alike: `elimination_round` and `round_eliminated` are inverse maps covering every model exactly once, the first `n_eliminated` rounds are `elimination_order`, each `pvalue` is the running maximum of `round_pvalue` up to its model's round, the deciding round is the first whose p-value reaches `options.alpha` with every earlier one below it, and Theorem 4 holds exactly on the result's own `alpha`. On five models whose mean losses step by more than a noise standard deviation the whole order is known in advance, and round `r` must drop the model with the `r`-th largest mean loss under both statistics; `round_statistic[0]` must match `mcs_statistic` under all three variances. `mcs_fwrite_rounds` is checked line by line — one line per round, each round's statistic, own p-value and running maximum in the promised format, the marker on the deciding round only — and `mcs_round_frame` column by column, for both a converged run and one forced never to converge at `alpha = 0.999`, which is also what first exercises the report's non-converged sentence: the assertion that had been written for it looked for text the report never printed, and passed only because no run reached it.

Adversarial: the smallest legal problem (two models, two observations, one bootstrap draw, blocks as long as the sample); both degenerate block lengths; a `hac_lag` far larger than the sample, which must clamp rather than read out of bounds; badly scaled losses at `1e6` and `1e-4`, where a t-statistic must be unchanged because it is scale free; and the all-identical-models input the variance floor exists for, checked for the exact degenerate path under `MCS_TR` and for structure and finiteness under `MCS_TMAX` (via `MISNAN`/`MISINF`, not libm's predicates, which `-ffast-math` may optimize away).

`STRESS=1` runs both statistics on 2000 observations of 10 models with 500 resamples. The whole file takes 0.03 seconds, with the stress runs too, best of three on the machine these documents were measured on. Verified clean under `-fsanitize=address,undefined` and under both the default `float` and the `MAT_DOUBLE` builds.

## `tests/correctness/mcs_primitives.c`

`tests/correctness/mcs_primitives.c`'s subject is the layer underneath those entry points. The header calls `mcs_gather`, `mcs_build_diffs`, `mcs_center`, `mcs_floor_var`, `mcs_hac_var_mean`, `mcs_tstat`, `mcs_reduce`, `mcs_worst_from_tstats`, `mcs_scratch_new`, `mcs_scratch_free` and `mcs_round` public "so a caller can run their own elimination loop"; eight of them had no direct call anywhere, and the claim that they compose back into `mcs()` had no test. Known values come from one 4 x 3 table — model 0 is `1,2,3,4`, model 1 is `2,2,2,2`, model 2 is `4,4,4,4` — whose every differential is written out in the test that uses it: the three pairs in the documented `(0,1), (0,2), (1,2)` order and the three "against the field" series, so the storage order is checked rather than inferred from a t-statistic computed on top of it. `mcs_hac_var_mean` and `mcs_tstat` get the same hand-computed Bartlett case the `dm_test` section of `docs/MCS_DOCUMENTATION.md` uses (`d = 0,1,2,3` at truncation lag 1, `2*pi*f = 1.5625`, a standard error of exactly `0.625`, `t = 2.4`), plus the constant series where the floor is what stands between the caller and `0/0`. `mcs_worst_from_tstats` gets a `MCS_TR` case whose answer lives entirely in the `t_ji = -t_ij` half that is never stored — all three stored t-statistics negative, so reading only them names model 0 and reading both halves names model 2 — and the all-tied case, which has to name the first model rather than depend on comparison order. `mcs_write_report` is checked against `mcs_fwrite_report` rendered into memory, byte for byte, and for overwriting rather than appending on a second call.

The check that file exists for is the last one. The test writes `mcs`'s elimination loop out again over the public primitives — allocating each round's scratch at that round's exact size where the round redraws, and allocating once where one set of resamples serves the whole run, which is what `mcs` itself does — and requires the two to agree *bit for bit* on everything discrete: the same survivors, the same elimination order, the same round for each model and the same deciding round, the same per-model and per-round p-values, the same `final_pvalue`. Not to a tolerance, because none of those is rounded — they are model indices, round numbers and counts of exceedances divided by the draw count, so anything but an exact match is a difference in behaviour. Each round's test statistic is floating-point arithmetic, and it is compared to `1e-12` relative: the manual loop inlines the same expression into a different caller than `mcs` does, and under `-ffast-math` the two copies have been measured one unit in the last place apart. Eleven panels cover both statistics and all three variances, and `STRESS=1` repeats it at 20 models and 500 resamples. Three of those panels are at two and three models. Two models is the one shape where `MCS_TR` forms fewer pairs than it has models, so a scratch sized by pairs has fewer per-draw slots than the shared path needs, and `mcs_scratch_new` widens it to two; the panel checks the shared tables fit there and the loop still reproduces `mcs`. Three models is the first shape with as many pairs as models. Before one set of resamples served every round, `mcs` and a caller's own loop reached a two-model round through different code, and these panels caught a version in which they accumulated the same sum in a different order. If the answer ever comes to depend on how the scratch was sized — a stride taken from the allocation rather than from the round, a buffer read past the current round's extent — the two disagree, and nothing else in the suite would see it. That is the failure a rewrite aimed at spending less memory introduces, which is why it is a correctness test here rather than left to `tests/performance/mcs_candidates.c`, which measures the memory.

That loop, like `mcs` and `mcs_tstats`, sets `MCSScratch.losses` under the bootstrap variance and so takes the shared path. The general path under the bootstrap variance — what `mcs_round` runs for a caller who has built `d` and not set `losses` — is otherwise reached only by `test_mcs_variance.c`, one round at a time, and here by one more test across a whole elimination. It cannot be compared with `mcs` round for round: it draws fresh resamples every round where `mcs` reuses the first round's, so from round two on their p-values differ by whole draws. Round one is where they coincide, since both draw `opt.bootstrap` resamples from a fresh stream in the same order. On four shapes, both statistics at 5 models over 200 observations and 9 models over 160, 250 resamples, blocks of 8, the test runs the manual loop with sharing turned off and requires round one's statistic to match `mcs` to `1e-12` relative, its p-value to within one draw, and the model it drops to be the same. The rest of that run is checked against itself: every model is dropped by exactly one round or left over, each MCS p-value is the running maximum of the round p-values up to its model's round, and the deciding round is the first whose p-value reaches `alpha`. Changing the general path's variance divisor to `opt.bootstrap - 1` fails all four shapes; the same change in the shared `MCS_TMAX` path fails the two `MCS_TMAX` shapes, through `mcs`.

## `tests/correctness/test_mcs_variance.c`

`tests/correctness/test_mcs_variance.c` is a simulation study rather than a check of known values: it runs the two panels described under **The three variances** in `docs/MCS_DOCUMENTATION.md` through `mcs_round` itself, writes `out/mcs_variance_size.txt`, and asserts the directions the documentation claims — that a HAC on a resample is the smaller of the two under dependence, that `MCS_VARIANCE_HAC_RESAMPLE` therefore gives a larger mean p-value than `MCS_VARIANCE_HAC` and a lower rejection rate than both of the others, that the bootstrap and sample-HAC variances stay within 0.02 of each other in mean p-value with dependence and without it, and that all three coincide to within 0.02 in mean p-value and in rejection rate once the dependence is switched off. It takes about three seconds, and the seeds are fixed, so the assertions are exact rather than probabilistic.

## `tests/correctness/mcs_size_and_power.c`

`tests/correctness/mcs_size_and_power.c` checks the property the procedure exists for, which none of the others can: Theorem 1's guarantee that the returned set contains every best model with probability at least `1-alpha`. That is a statement about repeated samples, so it is answered by simulation — 300 replications per panel, a complete null where every model is equally good and an alternative where one is strictly best, both statistics. It also measures where the guarantee does not hold: at 250 observations of AR(1) losses at `phi = 0.5` coverage is 0.920 for `MCS_TMAX` and 0.890 for `MCS_TR`, and the set is correspondingly too small. `docs/MCS_RELIABILITY_DOCUMENTATION.md` has the cause, established by sweeping the resample count, the sample length, the serial correlation and the block length one at a time, and what to do about it. On the default design it asserts coverage of at least 0.85 in every panel, a mean set below 3.5 of 5 models under the alternative, which is power, and above 4.0 of 5 under the complete null, which is what stops a procedure eliminating models it has no evidence against. It takes those four factors, and the replication count, from `MCS_SP_BOOTSTRAP`, `MCS_SP_OBS`, `MCS_SP_PHI`, `MCS_SP_BLOCK` and `MCS_SP_REPS`, and a swept run asserts nothing, since the thresholds are measurements of the default design.

## `tests/integration/frame_to_model.c`

`tests/integration/frame_to_model.c` covers the seam this header shares with `frame/`. `df_col_numeric` returns a column view whose stride is the frame's numeric column count, not 1, and two entry points here read a column that way: `mcs_loss` reads the actual series and each forecast, and `dm_test` reads both of its loss series. (`mcs` itself does not — it reads the frame's whole numeric block, which is contiguous by construction.) All three loss functions are built from a stride-ten view of `examples/datasets/us_real.csv` and again from `mat_copy` of the same columns, and the two must agree element by element, then produce the same confidence set, the same elimination order, the same round for each model and the same deciding round, and the same round statistics, round p-values and MCS p-values; `dm_test` is run on the same pair of loss series at stride ten and at stride two, and `mcs_pvalue_frame`'s `mean_loss` column, which reaches `stats_mean` through a view, is compared across the two arms. QLIKE is included because it is the one loss that divides by and takes the log of the forecast, so a stride bug there produces something wilder than a wrong number.
